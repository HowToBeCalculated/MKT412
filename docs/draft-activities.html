A practical map of the teaching goals, editable data, and simplifying assumptions behind Draft Studio.

Start with a teaching goal

These four drafts are small, functioning examples, designed to be copied and changed. All scenarios are fictional. There is no build step, API key, backend, external library, or saved student record in these drafts. Keep the standard HTML document, change the case data, and refresh the browser.

Give your agent the repository, then ask: “Read README.md, AGENTS.md, and this guide. Adapt one draft for my course while preserving existing activity URLs. Update the inventory and verify the interactions.” Claude Code loads the shared guidance through CLAUDE.md.

01 / Experimentation

A/B Test Detective →

Try: predict the better ad, reveal four checkpoints, and inspect the hidden rates. Reset and replay the same fictional visitors, or choose another scenario.

Change: SCENARIOS holds ad copy, underlying rates, and seeds; CHECKPOINTS holds visitor counts; wilson() computes approximate 95% intervals. Current counts finish at 5,000 per version; update sample generation and completion logic too if changing that horizon.

Assumptions: independent Bernoulli conversions, equal traffic, no time trends or audience confounding. Intervals describe each version at a fixed sample size. Repeated peeking is for demonstration; this draft does not supply a sequential testing rule or claim statistical significance.

Build next: minimum useful effect, test-plan worksheet, device segments, or a revenue metric. Formula reference: NIST confidence intervals.

02 / Competitive strategy

Positioning Map Studio →

Try: drag your brand and a rival. Use the sliders for the same operation with a keyboard. Inspect different segments, then try the empty corner.

Change: INITIAL_BRANDS defines perceived positions; SEGMENTS defines preferred positions and population weights (weights should total 1). TASTE_WIDTH changes tolerance for distance; NO_PURCHASE controls the outside option.

Assumptions: attractiveness = exp(−distance² / (2 × width²)); shares normalize attractiveness across four brands and no purchase, then weight by segment size. This is an invented illustrative choice model, not observed research. Perceived premium positioning is not a price input, and share is not profit.

Build next: price and contribution margins, research imports, extra segments, or repositioning costs. Keep coordinates in 0–100 and outside-option attractiveness positive.

03 / Resource allocation

Budget Allocation Challenge →

Try: reduce a channel before increasing another. Compare baseline results, launch a plan to reveal an event, and launch a revised mix. History preserves each committed mix and its event.

Change: CHANNELS holds capacity and scale; EVENTS holds channel multipliers; BUDGET is dollars available and MARGIN is contribution per acquired customer.

Assumptions: expected customers = capacity × (1 − exp(−spend / scale)); social spending adds up to 25% to email capacity. Contribution after media = customers × $45 − actual spend. No fixed overhead, repeat purchases, or duplicated customers across channels. All coefficients are invented; predictions are deterministic expectations.

Build next: let users hold the event constant across plans, add segment-specific curves, model overlapping audiences, or add more rounds. Events currently cycle in order, and history comparisons across events are not controlled experiments.

04 / Editorial judgment

AI Marketing Critique Arena →

Try: choose the stronger campaign, audit the indicated weaker draft, and compare your reasoning with the rubric. Work through all three briefs and discuss a rewrite.

Change: CASES contains brief, copy, stronger campaign, audited campaign, issues, explanations, rewrite, and discussion question. ISSUE_TYPES defines checkbox categories. Keep issue IDs and explanations synchronized.

Assumptions: these are hand-authored examples of AI-style drafts, not actual model output or automated fact-checks. Score = campaign-choice point + max(0, correct issue flags − extra flags). Each current brief has two rubric issues. It is a discussion aid, not an objective grade or a legal review.

Build next: ask students to write revisions, add alternative defensible answers, or use a local instructor rubric. Avoid supplying real student data or presenting invented endorsements as genuine.

Preview and verify an extension

From the repository root: python3 -m http.server 8000 --bind 127.0.0.1, then open localhost:8000. These four drafts also work as local files and offline; the older homepage and some original activities use CDNs.

  • Check the homepage card and the direct activity URL.
  • Exercise primary controls, reset, zero and extreme inputs, and feedback states.
  • Check the browser console, narrow screens, and keyboard access.
  • Verify model identities: segment shares sum to 1; no spend gives zero modeled customers; a zero-conversion interval stays within 0–1.
  • Keep drafts labeled until you have reviewed them for your course. Update pages/README.md when assumptions or dependencies change.

GitHub Pages publishes main from the repository root. A push to main updates the public site after its Pages deployment succeeds.
